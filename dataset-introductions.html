SWE-bench Pro

Software engineering · 真实 Agent · 当前复用范围：V1 / ARM64Real Agent · Current reusable scope: V1 / ARM64

它测什么？What does it evaluate?

面向真实软件仓库的代码修复任务。Agent 根据问题描述，在指定代码起点上读取文件、修改代码、运行测试并提交补丁；独立评分器通过测试结果判断修复是否成功。Code-repair tasks in real software repositories. An Agent reads and changes code, runs tests, and submits a patch from a specified starting commit. A separate evaluator uses tests to determine whether the repair succeeds.

一次运行如何进行？How does a run work?

  1. 锁定 V1 数据、官方 Agent 源码、任务代码起点和 ARM 容器镜像。Pin V1 inputs, official Agent sources, starting commits, and ARM container images.
  2. 从 benchmark 入口启动一个独立 Agent，通过已有模型 API 生成动作，在独立容器中执行工具。Launch an independent Agent from the benchmark entry. It calls an existing model API and executes tools in an isolated container.
  3. 保留逐步轨迹、工具输出、补丁和退出原因；在模型计时之外独立评分。Retain the step trace, tool outputs, patch, and exit reason; evaluate the patch separately from model timing.

当前能复用到什么程度？What is currently reusable?

通用环境、运行入口和用户文档位于 vllm-hust-benchmark。无需安装 Controller；只需已有兼容模型 API 和 ARM Docker 环境。当前锁定清单覆盖 8 道 NodeBB V1 任务，示例从其中 1 道、1 个 Agent 开始。它不是全量 V1/V2 的质量验收。The environment, runner, and user guide live in vllm-hust-benchmark. Controller is optional; an existing compatible model API and ARM Docker environment are sufficient. The current lock covers eight NodeBB V1 tasks, and the example starts with one task and one Agent. This is not full V1/V2 quality acceptance.

独立入口已通过真实 Agent 执行验证，但环境验收不等于修题成功。Submitted 只表示提交了补丁；只有独立评分输出完整，才能报告修复成绩。上下文超限、预算耗尽和未评分均须保留，不填成零分。The independent entry has been exercised by a real Agent. Environment acceptance does not prove a successful repair. Submitted means a patch was produced; a repair score requires complete independent evaluation. Context limits, exhausted budgets, and ungraded results remain explicit rather than becoming zero scores.

它与 SWE-smith 有什么区别？How is this different from SWE-smith?

这里运行的是根据新模型回复持续行动的真实 Agent。矩阵中的 SWE-smith 轨迹回放使用已保存的调用序列；回放吞吐或 program 完成率不能当作 SWE-bench Pro 的修题成功率，也不能相互替代。This workload runs a live Agent whose next action depends on new model responses. The matrix's SWE-smith trajectory replay uses saved call sequences. Replay throughput or program completion rate is not SWE-bench Pro repair success.
