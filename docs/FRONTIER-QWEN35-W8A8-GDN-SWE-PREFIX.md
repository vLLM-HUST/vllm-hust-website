# Qwen3.5-35B-A3B 新方法 W8A8 (GDN 变体) · 双卡 (TP2) SWE prefix reuse 并发曲线

本报告由实测产物直接生成, 数值零推断。每一档是一个独立的 900s 固定窗口观测, 五档在**同一个服务实例**内按 C1→C16 连续完成 (档间不重启服务、不重置 prefix cache),
因此档间唯一变量就是客户端并发 C。

**本页对应 series `swe-w8a8-gdn-tp2-20261016-mtp2` (TP2, 2×910B3)**。与已发布的 W8A8 TP2 曲线
(`swe-w8a8-tp2-20260929-mtp2-r2`) 使用同一份 prepared workload、同一个客户端、同一协议、同一服务参数、同一硬件型号与软件栈;
差别只有量化配方与所用卡对。

## 0. 与已发布 W8A8 点的配方差异

| 模块                                                           | 已发布 W8A8                  | 本 cohort |
| -------------------------------------------------------------- | ---------------------------- | --------- |
| `*self_attn*` (除 o_proj)                                      | W8A8 (int8 权重 + int8 激活) | 同左      |
| `*mlp.experts*`                                                | W8A8                         | 同左      |
| GDN `linear_attn.in_proj_qkv` / `in_proj_z` / `out_proj`       | BF16                         | **W8A16** |
| 其余 (o_proj / shared_expert / router / embed / lm_head / MTP) | BF16                         | 同左      |
| KV cache                                                       | bf16                         | 同左      |

`in_proj_z` 必须与 `in_proj_qkv` 同精度: vLLM 加载时把二者融合成一个 `MergedColumnParallelLinear` (`qwen3_5.py` 的
`packed_modules_mapping` 里 `"in_proj_qkvz"`), 而 `modelslim_config.is_layer_skipped_ascend()`
会在同一融合层分片精度不一致时直接抛错。

## 5. 口径限制 (必须与数值一起引用)

- 客户端与 engine 同机 (127.0.0.1), 客户端调度/JSON/网络开销仍在观测路径内
- 未做预热: 每个 play 使用新 cache_salt 冷启动, 窗口结束排空在途请求
- 本轮为 60s 资格窗口 + 900s 固定窗口两个显式测量, 无自动认证语义
- 首次冷编译: 因关闭 torch AOT autograd 缓存, 每轮启动都要重跑 torch.compile + ACL 图捕获, 该时间不计入测量窗口
- CANN 9.1 为逐进程临时环境 (未覆盖系统 8.5.0); 引擎实际加载的 CANN 版本见启动日志的 ASCEND_HOME_PATH
- 样例 workload 仅 8 条轨迹/360 轮, 非统计代表性 SWE 样本; 最长会话 141269 tokens, 未触及 262144 上限
- MTP 特有: 请求的 cudagraph_mode=FULL 被平台降级为 FULL_DECODE_ONLY (AscendGDNAttentionBackend 仅声明
  UNIFORM_BATCH)
- MTP 特有: 每次带 MTP 的运行都会留下一条不可用的 AOT 编译缓存条目, 故每轮实验前需隔离 torch_aot_compile/\*
- MTP 特有: 前缀复用可用, 但受 EAGLE/MTP 尾块丢弃语义影响, 每个请求比无 MTP 时少复用 1 个 block (2048 token)
- 三个 engine 补丁均为本地最小改动, 未进入上游; 若上游修复这些契约/版本错配, 本点的 mod 块需相应更新
- 配方特有: GDN 的 linear_attn 三个投影在本 cohort 为 W8A16 (int8 权重/bf16 激活), 与已发布 W8A8 cohort 的 BF16 不同; 两者在同一
  workload/协议/服务口径下可直接对照, 但本曲线本身不含 BF16 对照点
- 卡位特有: 本轮用 NPU 2,3, 已发布点用 0,1 —— 同一 CPU 亲和组、HCCS 全互联, 结构对等; NPU0 被用户常驻 TP1 服务占用, 不可用
- 同一服务实例内串行测 5 档, 各档不是统计独立重复; 不做重复性估计
