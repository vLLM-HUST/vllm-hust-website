Fast kernels still wait when the next wave is not ready. BetterScale combines FULL graphs, ordered replay, and device-side metadata preparation to shorten the host dependencies between inference steps.算子已经很快，设备却仍可能等不到下一波工作。BetterScale 通过 FULL graph、有序 replay 和 device 侧元数据准备，缩短相邻推理波次之间的 host 依赖与等待。

01

Capture the right work捕获真正该捕获的工作

Extend target FULL coverage to supported prefill/mixed shapes. Keep large context ingestion separate from the small draft proposal graph.为支持的 prefill/mixed 形状接通 target FULL。大规模 context 摄入与小规模 draft proposal graph 分开处理。

02

Shorten the dependency chain缩短执行依赖链

Use stream-ordered replay and CPU-side QLI bounds; in the admitted TP path, submit useful work before retiring receipts that need not block it.使用流内有序 replay 与 CPU 侧 QLI 边界；在已验收的 TP 路径中，先提交有效工作，再处理不必阻塞它的收据。

03

Give state a clear owner让状态有明确的所有者

On DP, owned input banks and captured device preparation decouple stable decode metadata from parts of the host preparation path.在 DP 中，通过独立输入槽位与捕获的 device 准备工作，将稳态 decode 元数据与部分 host 准备路径解耦。

04 / CAPACITY

Budget the program.
Use the remaining memory.量清执行成本，
把余量交给 KV。

Automatic physical sizing, one target/draft graph pool, and 1 GiB per rank of safety headroom. Both supported layouts admit a 512Ki-token context ceiling—not a guarantee that every active seat can hold a full-length request.按实际物理余量定容，target/draft 共用一个 graph 池，每 rank 保留 1GiB 安全量。两种配置支持 512Ki-token 上下文上限，不等于保证所有席位同时容纳满长请求。

TP8 · ≈14.94 GiB / rank

Real-weight startup and all 32 retained retrieval questions pass. Dummy long-history pressure reaches 96.84% KV usage: four 448Ki-input requests complete, with at most three running and the fourth queued.真权重启动与 32 道保留检索题全部通过。Dummy 长历史压力达到 96.84% KV 占用：四个 448Ki 输入请求全部完成，最多三个 running，第四个排队。

Running includes partial prefill; this is not three complete 448Ki prefixes resident at once. No preemptions occurred.Running 包含尚未完成的 prefill，不代表三个完整 448Ki 前缀同时驻留。该次没有发生抢占。

DP8 · ≈7.9 GiB / rank

Retained real-weight gates pass 32/32 retrieval and eight 60K-input requests; a separate 448Ki-input request completes. The longer pressure cohort timed out, so DP long-history saturation is not claimed.保留的真权重验收通过 32/32 检索和八个 60K 输入请求；另一次单 448Ki 输入完成。更长压力队列超时，因此不宣称 DP 长历史满池验收通过。

Capacity is separate from the historical throughput charts. Native hybrid-cache token equivalents depend on context and wave budgets. Prefix caching is supported from 0.4.1; the earlier 3GiB diagnostic preemption failure is not claimed fixed.容量结果与上方历史吞吐图分开。原生混合缓存等效 token 数随上下文和波次预算变化。0.4.1 起支持前缀缓存；此前 3GiB 诊断预算下的抢占恢复失败未声称修复。

05 / INTEGRATION

Your engine. Your command.
One explicit entry.你的引擎，你的命令。
一个显式接入点。

Install the patch package into an existing, working vLLM Ascend environment. The Worker composes independently scoped patches through the native lifecycle. It does not rebuild the engine or rewrite its environment.将补丁包装入已有、可工作的 vLLM Ascend 环境。Worker 通过原生生命周期组合职责独立的补丁，不重编引擎，也不重写运行环境。

python -m pip install --no-deps vllm-betterscale==0.4.1
# Add to your qualified native vllm serve command:
# --worker-cls betterscale.worker.Worker

Python 3.12+, vLLM 0.25.1, vLLM-Ascend 0.25.1rc1, torch-npu 2.10.0.post2. Selected upstream source files are checked at startup; matching version strings alone are not enough. Installation does not upgrade your runtime. The implementation is available under src/betterscale in the public repository.需要 Python 3.12+、vLLM 0.25.1、vLLM-Ascend 0.25.1rc1、torch-npu 2.10.0.post2。启动时还会核对选定上游源文件，版本号一致并不足够。安装不会升级你的运行环境；实现源码位于公开仓库的 src/betterscale。

BetterScale is open source under Apache-2.0. Install vllm-betterscale and select betterscale.worker.Worker; implementation and patches live directly in src/betterscale.BetterScale 以 Apache-2.0 开源。安装 vllm-betterscale，通过 betterscale.worker.Worker 接入；实现与补丁直接位于 src/betterscale。
