Fast kernels still wait when the next wave is not ready. BetterScale combines FULL graphs, ordered replay, and device-side metadata preparation to shorten the host dependencies between inference steps.算子已经很快，设备却仍可能等不到下一波工作。BetterScale 通过 FULL graph、有序 replay 和 device 侧元数据准备，缩短相邻推理波次之间的 host 依赖与等待。

01

Capture the right work捕获真正该捕获的工作

Extend target FULL coverage to supported prefill/mixed shapes. Keep large context ingestion separate from the small draft proposal graph.为支持的 prefill/mixed 形状接通 target FULL。大规模 context 摄入与小规模 draft proposal graph 分开处理。

02

Shorten the dependency chain缩短执行依赖链

Use stream-ordered replay and CPU-side QLI bounds; in the admitted TP path, submit useful work before retiring receipts that need not block it.使用流内有序 replay 与 CPU 侧 QLI 边界；在已验收的 TP 路径中，先提交有效工作，再处理不必阻塞它的收据。

03

Give state a clear owner让状态有明确的所有者

On DP, owned input banks and captured device preparation decouple stable decode metadata from parts of the host preparation path.在 DP 中，通过独立输入槽位与捕获的 device 准备工作，将稳态 decode 元数据与部分 host 准备路径解耦。

03 / VALIDATION

Performance, with
the checks beside it.性能旁边，
就是验收结果。

Both TP comparison arms pass the retained 32 original-input LongBench English retrieval questions through OpenCompass. The packaged DP Worker also passes 32/32.TP 对照与候选两组均通过 OpenCompass 中保留的 32 道 LongBench 英文检索题；打包后的 DP Worker 同样通过 32/32。

TP quality inputs: 9,921–14,997 tokens; 32-token output cap; 12 GiB KV/rank. This is a retrieval subset, not a complete quality certification.TP 质量输入为 9,921–14,997 tokens，输出上限 32 tokens，KV 为每 rank 12 GiB。这是检索子集验收，不是完整质量认证。

What these results do not establish这些结果尚不意味着

  • Stable end-to-end throughput or TTFT improvement稳定的端到端吞吐或 TTFT 改进
  • Higher maximum concurrency or KV capacity更高的最大并发或 KV 容量
  • Universal large-prefill speedups大 prefill 的普遍加速
  • All-mode N+2 scheduling or bubble-free execution全模式 N+2 调度或完全无气泡执行
04 / INTEGRATION

Your engine. Your command.
One explicit entry.你的引擎，你的命令。
一个显式接入点。

Install the patch package into an existing, working vLLM Ascend environment. The Worker composes independently scoped patches through the native lifecycle. It does not rebuild the engine or rewrite its environment.将补丁包装入已有、可工作的 vLLM Ascend 环境。Worker 通过原生生命周期组合职责独立的补丁，不重编引擎，也不重写运行环境。

python -m pip install --no-deps vllm-betterscale==0.3.0
# Add to your qualified native vllm serve command:
# --worker-cls betterscale.worker.Worker

Python 3.12+, vLLM 0.25.1, vLLM-Ascend 0.25.1rc1, torch-npu 2.10.0.post2. Selected upstream source files are checked at startup; matching version strings alone are not enough. Installation does not upgrade your runtime. The public Worker is an identity alias of the qualified implementation.需要 Python 3.12+、vLLM 0.25.1、vLLM-Ascend 0.25.1rc1、torch-npu 2.10.0.post2。启动时还会核对选定上游源文件，版本号一致并不足够。安装不会升级你的运行环境；公开 Worker 就是已验收实现的同一类。

Already using the old strengthen-dsv4 distribution? Stop the service and uninstall it first: the two distributions share implementation files. The development repository remains private; the Python package and its source are public on PyPI.若已安装旧 strengthen-dsv4 包，请先停服并卸载旧包：两个发行包共享实现文件，不能同时安装。开发仓库仍为私有，Python 包及其源码已在 PyPI 公开。
