01 / GDN core + metadata builder

Keep mixed work in graphs让 mixed 请求留在图里

Before · 原来 · The native GDN prefill branch gathers and transposes recurrent state, then writes it back; mixed batches also split and rejoin work.原生 GDN prefill 分支取出、转置 recurrent state，计算后再写回；混合批次还需拆分与拼合。

BetterScale · Capacity-keyed FULL graphs read request lengths and state slots from metadata. Owned GDN operates directly in the persistent K-V state pool.FULL 图按 token 容量选择，请求长度与状态位置由 metadata 表达。自有 GDN 直接操作持久 K-V 状态池。

02 / GDN preprocessing + chunk kernels

Do less surrounding work减少核心计算周边的工作

Before · 原来 · Packing Q/K/V, normalization, gates and intermediate layout preparation add small kernels and memory traffic around the core.Q/K/V 整理、归一化、gate 与中间布局准备，在核心计算周围产生小算子和访存。

BetterScale · Fuse preprocessing, share intermediate layouts and skip empty triangular-solve tasks. This does not remove every layout conversion.融合预处理、复用中间布局，跳过空 chunk 的三角求解；并非消除了所有布局转换。

03 / FIA + runner / graph boundary

Publish once per wave每波准备，不再逐层更新

Before · 原来 · Native FULL attention still uses per-layer host task updates and a host replay barrier to protect that update protocol.原生 FULL attention 仍有逐层 host 图任务更新，并用 replay 的 host 等待保护更新协议。

BetterScale · Run one native FIA plan per wave; publish banked metadata with upload/consume fences. Replace the old update barrier with the owned ordering protocol.每波只运行一次 native FIA 规划；按 bank 发布 metadata，用上传／消费事件保护复用，以自有顺序协议替代旧更新等待。
