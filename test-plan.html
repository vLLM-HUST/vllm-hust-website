方法与统计详情

有效算力：同轮 F、T 与参考分母

MMLU200，每题最多输出 256 词元，两侧各 3 轮。在同一次执行内取得有效算量 F 的必要记录和双卡同步墙钟时间 T，以同轮标识关联。提交、执行、搬运、通信、同步、空闲及同轮计量开销全部计入 T，并记录实际计数或插桩方式。

复用适用于当前模型、精度、卡数和工况的独立计算、访存及通信标定原件，保留原始分母统计、配置、参考图及适用性依据。参考图包含必要操作依赖、资源串行约束和卡间通信，参考方法及分母统计在正式测试前固定。

finish(v) = d(v) + max{finish(u): u → v}
T参 = max_v finish(v)  （无前序时 finish(v) = d(v)）
C = ΣF / (k × ΣT × 10¹²)
C参 = ΣF / (k × ΣT参 × 10¹²)
η = 100 × C / C参 = 100 × ΣT参 / ΣT

k=2，C 与 C参单位为 TFLOPS/芯片。三轮先求和再相除。F 按最终有效输出的必要依赖统计：矩阵乘法 2MNK，MoE 按实际激活专家，注意力按实际执行结构计量；填充、无贡献的重复计算、无输出依赖的草稿和缓存已省去的计算排除，必要中间计算计入一次。

C下界 = ΣF下界 / (k × ΣT × 10¹²)
C参上界 = ΣF上界 / (k × ΣT参下界 × 10¹²)
η下界 = 100 × C下界 / C参上界

按区间核算时使用上述参考算力上界和效率下界；必要工作量相同时，η 可化简为参考时间与实测时间之比。

存在未唯一确定的执行分支时，取可行分支共有的必要操作和依赖，计算参考时间及效率下界，注明取界范围，以效率下界判定。AI Core 利用率与参考效率分别列示。

配对、预热、评分与时延

两臂固定相同权重、分词器、硬件、请求顺序、预算及评分规则，分别完成覆盖输入长度、并发、活跃请求数及执行图路径的预热。确认正式请求所需形状的 JIT 编译已完成后计时。逐场景固定质量比较规则与允许差异、Schema、SLO、并发、超时、重复次数和重试处理。

吞吐=成功输出词元数/整批墙钟秒数，区间从首请求发出至正式请求全部完成或按规则终止，包含排空、失败及超时耗时。TTFT 从请求发出到首个模型输出词元事件；TPOT=(完成时刻−首词元时刻)/(输出词元数−1)，用于输出多于 1 词元的成功请求。均值逐请求等权，列出有效数与排除数。五项分位数在 (n−1)q 处线性插值。

MMLU 使用规则评分。HLE、Frontier 共用同一冻结辅助裁判，复用现有同一模型权重，由脚本独立运行和计时，输出上限 8192；记录模型、运行时、输入模板、语法及解析器。评分耗时单列，求解性能和成本统计求解阶段。保留原计划评分分母，失败与未决计入未正确项，结构化输出另列 Schema 合规率。

公开轨迹保留原输入及工具历史，核对请求、响应和结束状态完整性；逐请求独立缓存盐，两侧分词结果与冻结校验值一致。

长上下文：三档输入与五个窗口

使用冻结的 5 个真实公开任务历史，完整输入分档为 [4096,8192)、[16384,24576)、[32768,49152) 词元。保留各档首条合格请求、来源、顺序与校验值，模型最大长度至少 49408。

每档并发 8，temperature=0、seed=17、ignore_eos=true，固定输出 256，逐请求独立缓存盐，超时 600 秒，自动重试 0。完成启动预热后每档再预热 60 秒、正式提交 300 秒，然后排空。按请求发出时间划分五个 60 秒提交窗口，分别跟踪至结束。

窗口吞吐=该组成功输出词元数/窗口开始至该组最后请求结束的秒数；整段吞吐独立计算并包含排空。专项 P95/P99 采用最近秩法，第 ⌈0.95n⌉ / ⌈0.99n⌉ 项，列出样本数。各档和窗口须有有效样本、正的分母；正式请求全部成功结束，超时、失败、漏回、OOM、死锁、非预期服务退出及静默截断均为 0。正常生成至固定预算记为长度终止。

成本：实际费用与完整区间利用率

里程碑使用 MMLU200 完整回答、并发 200、输出上限 8192、正常 EOS，并满足相同质量与服务要求。结题使用 4K 档输入、固定输出 256；4 个独立逻辑租户队列共享引擎，每租户并发 6，总并发 24，阶段预热 60 秒、正式提交 300 秒并排空。

A = P × k × T / (30 × 24 × 3600)
c = 10⁶ × A / N
成本降幅 = 100 × (1 − c_B1 / c_B0)
U = Σ(逐卡利用率 × 覆盖秒数) / Σ逐卡覆盖秒数

P 为每卡实际综合月费，包含占卡及相应主机、内存、电力、运维，同项计入一次；两张实际占用卡固定费用全额计入。T 从正式提交至最后正式请求结束；N 为区间发起并成功结束请求的输出量。正式成本使用实际费用凭据，公开报价同费率估算另列。

两卡利用率完整覆盖同一计量区间，以采样时钟中点观测、前值保持并裁切，列出周期、覆盖秒数、空档及最大保持间隔，按卡时加权。80% 用于完整区间均值，分窗曲线展示波动。四租户均完成请求，失败、超时及漏回均为 0；判定数据须满足 N 和基线成本为正、采样完整覆盖及两侧条件可比。

执行、复用与交付记录

已有记录经版本、同轮对应关系、预算和参考适用性核验后复用。缺失或无效记录补充对应测试，复核受影响指标，保留原始结果及异常处理。归档 Release、源码、镜像、MOD、实际配置、脚本、请求清单、预热、响应流、计时、评分、参考分母、费用、设备采样及复算表。生成和评分按固定预算执行，实际耗时按阶段记录。

Methods and statistics

Effective compute: same-run F, T and reference denominator

MMLU200, at most 256 output tokens, three repetitions per arm. Record the evidence needed for effective work F and synchronized two-chip wall time T in the same execution, linked by run ID. Include submission, execution, transfers, communication, synchronization, idle time and measurement overhead in T; disclose counting and instrumentation.

Reuse independent compute, memory and communication calibration applicable to the model, precision, chip count and workload. Retain the original denominator statistics, configuration, reference graph and applicability evidence. Include required operation dependencies, resource order and inter-chip communication. Fix the reference method and denominator before formal testing.

finish(v) = d(v) + max{finish(u): u → v}
T_ref = max_v finish(v)  (no predecessor: finish(v) = d(v))
C = ΣF / (k × ΣT × 10¹²)
C_ref = ΣF / (k × ΣT_ref × 10¹²)
η = 100 × C / C_ref = 100 × ΣT_ref / ΣT

k=2; C and C_ref are TFLOPS/chip. Sum all three repetitions before division. Count necessary dependencies of final useful output: matrix multiplication 2MNK, actual activated MoE experts and executed attention structure. Exclude padding, unproductive duplication, unused draft work and work avoided by cache hits; count necessary intermediate work once.

C_lower = ΣF_lower / (k × ΣT × 10¹²)
C_ref_upper = ΣF_upper / (k × ΣT_ref_lower × 10¹²)
η_lower = 100 × C_lower / C_ref_upper

For interval accounting, use these reference-compute upper and efficiency lower bounds. With identical necessary work, η simplifies to the reference/measured time ratio.

For unresolved execution branches, retain the required operations and dependencies shared by feasible branches. Report the reference-time and efficiency lower bounds, their scope, and use the efficiency lower bound for acceptance. Report AI Core utilization separately.

Pairing, warmup, grading and latency

Match weights, tokenizer, devices, request order, budgets and grading rules. Warm both arms across input lengths, concurrency, active requests and graph paths. Start timing after JIT compilation covers every shape needed by formal requests. Freeze quality comparison and tolerances, Schema rules, SLOs, concurrency, timeouts, repetitions and retry handling per workload.

Throughput = successful output tokens / batch wall seconds, from first submission until all formal requests complete or terminate under the frozen rule, including drain, failures and timeouts. TTFT ends at the first model-output token event. TPOT=(completion−first token)/(output tokens−1), defined for successful requests with more than one output token. Average requests equally and disclose valid and excluded counts. Fixed-profile percentiles use linear interpolation at (n−1)q.

MMLU uses rule grading. HLE and Frontier share a frozen auxiliary judge using the existing model weights, run and timed separately, with an 8192-token output cap. Pin model, runtime, input template, grammar and parser. Report grading time separately; solver performance and cost cover the solver phase. Keep the planned grading denominator, count failed and unresolved judgments as not correct, and report Schema compliance separately.

Public traces retain the original inputs and tool history. Check request, response and termination completeness. Use independent request cache salts and match both arms’ tokenization to the frozen checksums.

Long context: three input bands, five windows

Use the frozen five real public task histories with complete inputs in [4096,8192), [16384,24576), [32768,49152) tokens. Preserve the first eligible request per band, source, order and checksum. Maximum model length is at least 49408.

Per band: concurrency 8, temperature=0, seed=17, ignore_eos=true, fixed 256 output tokens, independent request cache salts, timeout 600 seconds and 0 automatic retries. After startup warmup, warm each band for 60 seconds, submit for 300 seconds and drain. Assign requests by submission time to five 60-second windows and follow each group to completion.

Window throughput = successful group output tokens / seconds from window start to its last completion. Compute whole-phase throughput independently, including drain. Use nearest-rank P95/P99 at ⌈0.95n⌉ / ⌈0.99n⌉ and report n. Every assessed band and window needs valid samples and positive denominators. All formal requests must succeed; timeouts, failures, missing responses, OOM, deadlock, unexpected exits and silent truncation must be 0. Normal completion at the fixed budget is length termination.
