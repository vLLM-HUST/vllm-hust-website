01 / TWO ENTRY POINTS

Analyze offline. Observe at runtime.独立分析。运行时观测。

01 / OFFLINE

Analyze what you already have.已有 trace，直接分析。

Run the native analyzer on profiler databases. Recover reusable structure, apply optional YAML model hints, compare occurrences, and export an AugDB or Perfetto timeline. No vLLM plugin is required.对 profiler 数据库运行原生分析器。恢复可复用结构、应用可选 YAML 模型提示、比较不同实例，并导出 AugDB 或 Perfetto 时间线。不要求安装 vLLM 插件。

02 / RUNTIME PLUGIN

Bring scheduling into the picture.把调度上下文带进来。

Select the observer with --scheduler-cls. Record scheduling decisions and available request/cache metadata. For step-to-device analysis, add the explicit identity-transport and worker-marker patch.通过 --scheduler-cls 选择观测插件，记录调度决策及可用的请求、缓存元数据。需要 step 到设备关联时，再启用显式的身份传递与 worker 标记补丁。

One definition can have many measured instances. Folding repeated work does not erase instance boundaries or change event timestamps. YAML hints can identify model-specific units; recorded step identity can constrain candidate boundaries. These are distinct evidence sources, not an assertion that every semantic layer is inferred automatically.一个结构定义可以对应多个实测实例。折叠重复工作不抹去实例边界，也不改写事件时间戳。YAML 提示可以标识模型特定单元；记录到的 step 身份可以约束候选边界。这些证据各有来源，不意味着所有语义层都能自动推断。

03 / GRAPH REPLAY

A replay is not a black box.Replay，不止一个黑盒。

TraceLoom reconstructs supported replay units and their exact operator members. Keep the outer unit protected while recovering structure inside it, comparing concrete launches, and inspecting cost and source evidence. Concurrent streams retain their own coordinates; visual ordering is not a claim of causality.TraceLoom 重建有证据支持的 replay 单元及其精确算子成员。保护外层单元边界，同时恢复内部结构、比较具体 launch，并查询耗时与原始证据。并发 stream 保留各自坐标；显示顺序不等于因果依赖。

Step → launch → exact membersStep → launch → 精确成员

Runtime identity connects the scheduler decision to a launch, then follows reconstructed membership into the graph. No nearest-time assignment and no inference from overlap alone. Step-constrained candidates preserve replay boundaries and shared definitions. In 0.1.4, ordinary events and replay members share one device-event plane, and their structural nodes share the same projection. Only actual overlap creates extra event lanes; stream and replay identities stay in attributes, not extra tracks or containers.运行时身份把调度决策关联到 launch，再沿重建的成员关系进入 graph。不按最近时间分配，也不只凭重叠猜归属。Step 约束下的候选匹配保留 replay 边界与可复用定义。0.1.4 的 Perfetto 导出让普通事件与 replay 成员共用 device 事件平面，结构节点也使用同一套投影。仅实际重叠才增加事件泳道；stream 与 replay 身份保留为属性，不额外增加泳道或容器。

05 / GET STARTED

Choose your entry point.选择适合你的入口。

A. Standalone analysisA. 独立分析

One Python package includes the native analyzer, CLI, Python interface and runtime observer. Linux ARM64 / x86-64 wheels (glibc ≥ 2.28, Python ≥ 3.10) need no separate native installation. Source builds require a C++17 toolchain, SQLite and libyaml development libraries. Gzip export uses system gzip.一个 Python 包包含原生分析器、CLI、Python 接口与运行时观测插件。Linux ARM64 / x86-64 wheel（glibc ≥ 2.28、Python ≥ 3.10）无需另装原生分析器。源码构建需要 C++17 工具链、SQLite 与 libyaml 开发库；gzip 导出使用系统 gzip。

python -m pip install traceloom==0.1.4
traceloom /path/to/profile.db --output analysis.db
traceloom export-perfetto analysis.db \
  --output timeline.perfetto.json.gz

B. Runtime pluginB. 运行时插件

Install into an existing compatible vLLM environment. This entry records scheduler context without a source patch; it does not yet associate device work.安装到已有的兼容 vLLM 环境。此入口无需源码补丁，只记录 scheduler 上下文，尚不建立设备关联。

python -m pip install traceloom==0.1.4
export TRACELOOM_CONTEXT_DIR=./traceloom-context
export TRACELOOM_RUN_ID=inference-study-001
vllm serve /path/to/model --async-scheduling \
  --scheduler-cls traceloom.vllm.TracingAsyncScheduler \
  --host 127.0.0.1 --port 8000

Synchronous scheduler: use TracingScheduler and omit --async-scheduling. Existing worker-class selection stays unchanged. Custom scheduler composition is not automatic.同步调度使用 TracingScheduler 并省略 --async-scheduling。不替换已有 worker class；不自动兼容其他自定义 scheduler。

From Python: analyze, query, export.在 Python 中：分析、查询、导出。

import traceloom

result = traceloom.analyze("profile.db", output="analysis.db")
rows = result.query(
    "SELECT * FROM traceloom_v_position_occurrence WHERE position_id = ?",
    ("node-N003",),
)
result.export_perfetto("timeline.perfetto.json.gz")

Connect steps to devices, then constrain recovery把 step 关联到设备，再约束结构恢复

Use LinkedTracingAsyncScheduler with the explicit transport-worker.patch on an audited, task-owned vLLM checkout. Enable the normal profiler. Import every relevant producer JSONL, using its actual emitted filename. Scheduler-only files are insufficient for step-constrained recovery.在已审计、独立的 vLLM checkout 应用显式 transport-worker.patch，选择 LinkedTracingAsyncScheduler 并启用原有 profiler。使用实际生成的文件名，导入所有相关 producer JSONL。仅 scheduler-only 文件不足以启用 step 约束恢复。

from pathlib import Path
import traceloom

result = traceloom.analyze(
    "profile.db", output="step-analysis.db",
    context=sorted(Path("traceloom-context").glob("*.jsonl")),
    rules_config=traceloom.bundled_rules("scheduler-step"),
)
result.export_perfetto("step-timeline.perfetto.json.gz")

This rule supports eager recovery and exact graph replay linked to scheduler steps. A protected replay must have one known step identity; missing or conflicting evidence is rejected. Simultaneous marked-structure projection remains unsupported.此规则支持 eager 恢复，以及与 scheduler step 精确关联的 graph replay。受保护的 replay 必须属于一个已知 step；证据缺失或冲突时拒绝约束恢复。仍不支持同时启用 marked-structure 投影。

Disable recording by unsetting TRACELOOM_CONTEXT_DIR; remove the adapter by restarting without the custom scheduler class. Protect captured metadata. This is a native scheduler-class plugin, not an Extension Manager bundle or automatic entry-point hook.取消设置 TRACELOOM_CONTEXT_DIR 可关闭记录；移除自定义 scheduler 参数并重启即可移除适配器。请保护采集元数据。它通过原生 scheduler 类接入，不是 Extension Manager bundle，也不是自动加载的 entry-point hook。
