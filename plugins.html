vLLM-HUST Extension and Integration ArchitecturevLLM-HUST 扩展与集成架构

Domain contracts first; bundles second.先定义领域契约，再定义 bundle 交付。

TRANSITIONTyped contracts · explicit boundaries类型化契约 · 显式系统边界

The former entry-point-based Plugin Standard 1.0 remains a legacy compatibility profile during migration. It is not the universal architecture for platform profiles, external KV systems, control planes, or device hot paths.原有基于 entry point 的 Plugin Standard 1.0 在迁移期间仅作为 legacy compatibility profile；它不再被视为平台 profile、外部 KV 系统、control plane 或设备热路径的统一架构。

  1. 01Classify分类

    Identify the system role before choosing a delivery mechanism.先确定系统角色，再选择交付机制。

  2. 02Contract领域契约

    Select the scheduler, worker, platform, operator, telemetry, or bridge contract actually owned by the host process.选择由对应 host 进程真正拥有的 scheduler、worker、platform、operator、telemetry 或 bridge 契约。

  3. 03Describe描述

    Declare bundle identity, host API range, components, execution planes, isolation, and permissions in a closed manifest.在闭合 manifest 中声明 bundle 标识、host API 范围、组件、执行面、隔离与权限。

  4. 04Configure配置

    List exact manifest paths; the runtime performs no implicit package or filesystem scan.列出精确 manifest 路径；运行时不会隐式扫描包或文件系统。

  5. 05Admit准入

    Fail closed on schema, API range, duplicate ID, allowlist, permission, or isolation errors before implementation import.在实现 import 前，对 schema、API 范围、重复 ID、allowlist、权限或隔离错误 fail closed。

  6. 06Snapshot快照

    Freeze one deterministic process-local view without resolving domain conflicts generically.冻结确定性的进程本地视图，但不由通用加载器解决领域冲突。

  7. 07Materialize实例化

    Let only the owning domain and execution plane instantiate the component.只允许拥有该领域契约和执行面的代码实例化组件。

  8. 08Verify & roll back验证与回退

    Prove equivalent behavior and failure handling before recommending the typed path; retain a tested legacy rollback.推荐类型化路径前验证等价行为与故障处理，并保留经过测试的 legacy 回退。

BUNDLE ≠ ROLE

Delivery stays separate交付与角色分离

A bundle may contain multiple components. It does not turn a KV system, platform profile, or control plane into one generic plugin.一个 bundle 可以包含多个组件，但不会把 KV 系统、平台 profile 或 control plane 变成一种万能插件。

EXPLICIT DISCOVERY

No core-owned scan核心不扫描扩展

Only explicit vllm-hust-ext extension commands inspect installed Bundle metadata. Normal vLLM import and startup never invoke the manager.只有显式的 vllm-hust-ext 扩展命令检查已安装 Bundle metadata；普通 vLLM import 与启动不会调用管理器。

FAIL CLOSED

Reject before import在 import 前拒绝

Unknown fields, contracts, permissions, isolation, duplicate identities, and incompatible API ranges stop startup.未知字段、契约、权限、隔离、重复标识和不兼容 API 范围都会阻止启动。

PROCESS OWNERSHIP

Materialize by domain按领域实例化

Scheduler and worker connectors remain separate components. The generic loader never chooses provider precedence or invokes hot-path callbacks.scheduler 与 worker connector 保持为独立组件；通用加载器不选择 provider 优先级，也不调用热路径 callback。

PERMISSIONS

Declaration is not a sandbox声明不等于沙箱

Non-empty permissions are denied by default. Trusted in-process code still has host authority; unsupported isolation cannot be claimed.非空权限默认拒绝；可信进程内代码仍拥有 host 权限，不能宣称未实现的隔离能力。

COMPATIBILITY

Behavior, not import success兼容是行为而非 import 成功

Manifest admission proves only static compatibility. A component graduates after domain behavior, failure, shutdown, and rollback tests pass.manifest 准入只证明静态兼容；组件必须通过领域行为、故障、关闭和回退测试后才能毕业。

One materializer does not prove ecosystem compatibility一个 materializer 不代表生态兼容已经完成

The historical core-owned Bundle prototype validated and snapshotted descriptors before implementation imports. The first experimental materializer supports one exclusive scheduler victim-selector provider. Zero typed providers retain legacy auto-discovery; an explicit victim_selector_plugin must select exactly one legacy provider, and its discovery, load, factory, or protocol failures fail closed. Typed ambiguity and typed import or protocol failures also fail closed. The KV domain validates exact scheduler, worker, and API-plane telemetry components, explicit ordered composition, and declared HMA, piecewise, and cache-layout capabilities without importing implementations. Typed single and ordered_multi selections now materialize through KVConnectorFactory: configuration checks import nothing, each process imports only its selected roles, declaration mismatches fail closed, and ordered child configuration plus telemetry are keyed by logical connector ID instead of class name. Conflicting ordered layouts fail before import. The four built-in Mooncake direct/store and LMCache v1/multiprocess names pass a bounded factory-level legacy/typed gate for exact class and role resolution, telemetry codec shape, next-start rollback names, and equivalent optional-dependency failure. This is materialization equivalence, not service, lifecycle, accelerator, or performance equivalence. KVTransferConfig keeps typed and legacy paths mutually exclusive, and the legacy MultiConnector path forwards recovery lifecycle signals across its children. BidKV's installed legacy/typed contract replay now passes for victim choices, metrics, snapshots, initialization failure, next-start rollback, and emergency disable. It remains experimental because this is deterministic contract replay, not real online workload, accelerator, or performance evidence. API-plane IO processors now use an explicit qualified typed selector while unqualified names retain legacy behavior. Typed stat loggers fan out with distinct legacy providers and deduplicate a class published through both paths. Their selected import, type, and initialization failures fail closed. The typed KV paths remain experimental until real Mooncake, LMCache, PegaFlow, and LMCache-Ascend equivalence and rollback gates pass. The official CPU image still fails 17 of 96 upstream-identical fused-MoE BF16 vec cases, so CPU support and release-candidate promotion remain blocked. The exact kernel, test, and tolerance files match upstream main; focused diagnostics also show that fast-exp alone and reference accumulation order do not explain the failures. The release record keeps this failed result visible instead of changing unrelated extension code or widening a kernel tolerance.生态重组的兼容与回退专项门禁已经通过，因此可以保持 opt-in 与实验性标签发布；但官方 CPU 镜像在与上游完全相同的 fused-MoE BF16 vec 矩阵中仍有 17/96 个 case 失败，所以 CPU 支持声明与 release-candidate 晋级继续阻塞。内核、测试和容差文件与 upstream main 一致，专项诊断也表明 fast-exp 本身及参考累加顺序都不足以解释失败。release record 会保留这个失败结果，不会修改无关扩展代码或放宽内核容差来掩盖它。

Real-run readiness is recorded separately真实运行就绪度单独记录

The LMCache-Ascend preflight launches no service and rejects namespace-only imports. On host 112 it verified the model, ports, eight NPUs, bundle roles, revisions, exact core source, engine import, and runnable vLLM CLI. It then blocked because the provider's generated version module, LMCache 0.4.4, and torch-npu were absent from the isolated runtime. This is environment-readiness evidence, not a connector, hardware, or performance result.LMCache-Ascend preflight 不启动任何服务，也不会接受仅有 namespace 的 import。在 host 112 上，模型、端口、8 张 NPU、bundle 角色、版本、精确 core 源码、engine import 与可运行 vLLM CLI 均通过；隔离运行环境缺少 provider 生成的版本模块、LMCache 0.4.4 与 torch-npu，因此在启动前阻塞。这是环境就绪度证据，不是 connector、硬件或性能结果。

Mooncake runs are process-owned and mode-exclusiveMooncake 运行由本次进程持有且模式互斥

The direct runner executes exactly one fresh-start state: legacy, typed, or rollback. It retains one process group per prefiller, decoder, and proxy, fails when a child exits during readiness, probes the proxy's actual OpenAPI route, and maps remote HUP plus normal signals to bounded cleanup of only those children. Typed manifest variables are absent from legacy and rollback. This is a safe comparison harness, not Mooncake behavior evidence by itself.direct runner 每次只执行一个全新启动状态：legacy、typed 或 rollback。它分别持有 prefiller、decoder 与 proxy 的进程组，在就绪阶段发现子进程退出即失败，检查代理实际存在的 OpenAPI 路由，并将远程 HUP 和普通信号统一映射到仅针对这些子进程的有界清理；legacy 与 rollback 不含 typed manifest 环境变量。这是安全的对比 harness，本身不构成 Mooncake 行为证据。

Mooncake admission includes live resourcesMooncake 准入包含实时资源

A controlled A100 runtime reached Mooncake 0.3.10, Torch 2.11, exact core CLI, and healthy real 7B prefill/decode services. No benchmark ran: the former harness expected a nonexistent proxy /health route, and SSH interruption exposed a missing HUP cleanup path. The exact child groups were terminated without touching other services; both defects are fixed and tested. Before a fresh matrix, an unrelated 32B service reclaimed both GPUs and port 18000, so final-revision preflight correctly rejected both GPUs below 20,000 MiB. This is startup and blocked-admission evidence, not a Mooncake failure or real-online result.受控 A100 运行环境已达到 Mooncake 0.3.10、Torch 2.11、精确 core CLI，并让真实 7B prefill/decode 服务进入健康状态。由于旧 harness 错误等待不存在的代理 /health 路由，且 SSH 中断暴露出缺少 HUP 清理路径，benchmark 并未执行；三个精确子进程组随后在不触碰其他服务的情况下被终止，两项缺陷均已修复并测试。新的矩阵启动前，一个无关的 32B 服务重新占用了两张 GPU 与 18000 端口，因此最终提交的 preflight 正确判定两张卡空闲显存低于 20,000 MiB。这是启动与准入阻塞证据，不是 Mooncake 失败或 real-online 结果。

Historical prototype evidence (superseded)历史原型证据（已被新架构取代）

  • Default startup performs no manifest or package scan; only explicitly selected installed IDs inspect distribution metadata.默认启动不扫描 manifest 或已安装包；只有显式选择的已安装 ID 才会检查 distribution metadata。

  • Schema and runtime contract vocabularies remain identical.schema 与运行时契约词汇保持完全一致。
  • Compatibility and policy errors fail before implementation import.兼容与策略错误在实现 import 前 fail closed。
  • Scheduler policy selection is exclusive, qualified when ambiguous, and fail-closed after typed admission.scheduler policy 采用独占选择，多 provider 时用全限定名消歧，typed 准入后失败不会静默降级。
  • API-plane IO processors use qualified typed selection; stat loggers use typed fan-out with legacy migration deduplication.API-plane IO processor 使用全限定 typed 选择；stat logger 使用 typed fan-out，并对 legacy 迁移双路径去重。
  • KV topology names exact scheduler, worker, and API telemetry providers, rejects cache-layout conflicts, and preserves explicit MultiConnector order without importing implementations.KV 拓扑精确指定 scheduler、worker 与 API telemetry provider，拒绝 cache-layout 冲突，并在不 import 实现的情况下保持显式 MultiConnector 顺序。
  • Built-in Mooncake and LMCache bridge names preserve legacy class, role, telemetry-codec, rollback-name, and missing-dependency materialization behavior.内置 Mooncake 与 LMCache bridge 名称保持 legacy 类、角色、telemetry codec、回退名称与依赖缺失时的材料化行为。
  • Legacy entry-point behavior remains available when no typed scheduler provider is admitted.未准入 typed scheduler provider 时，legacy entry-point 行为继续可用。
  • No lifecycle or performance claim is inferred from admission or one materializer alone.不会仅凭准入或单个 materializer 推断完整生命周期或性能结论。
