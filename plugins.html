Architecture rule

Classify the role before the delivery mechanism.

A plugin bundle delivers components; a KV connector adapts vLLM to a state system; a control plane makes external decisions through a narrow bridge. Platform profiles, Mooncake, LMCache, PegaFlow, policies, tools, and applications retain their distinct system identities.

Why vLLM-HUST为什么选择 vLLM-HUST

Replaceable policy, state, execution, and hardware paths—with evidence attached.策略、状态、执行与硬件路径可替换，并为结果附上证据。

The technical edge is the combination: programmable scheduling and KV policy surfaces; graph-aware decoding, MoE, and precision paths; explicit Ascend and Metal capability negotiation; narrow control-plane actions; and matched results with exact provenance and rollback. Available code, published work, and open designs remain separate evidence levels.技术亮点来自完整组合：调度与 KV 策略可编程，解码、MoE 与精度路径感知计算图，Ascend 与 Metal 能力显式协商，上层控制动作保持窄接口，并以 matched 结果、精确版本和回退闭合证据链。已有代码、发表成果和开放设计始终分层展示。

vLLM-HUST Extension and Integration ArchitecturevLLM-HUST 扩展与集成架构

Domain contracts first; bundles second.先定义领域契约，再定义 bundle 交付。

TRANSITIONTyped contracts · explicit boundaries类型化契约 · 显式系统边界

The former entry-point-based Plugin Standard 1.0 remains a legacy compatibility profile during migration. It is not the universal architecture for platform profiles, external KV systems, control planes, or device hot paths.原有基于 entry point 的 Plugin Standard 1.0 在迁移期间仅作为 legacy compatibility profile；它不再被视为平台 profile、外部 KV 系统、control plane 或设备热路径的统一架构。

  1. 01Classify分类

    Identify the system role before choosing a delivery mechanism.先确定系统角色，再选择交付机制。

  2. 02Contract领域契约

    Select the scheduler, worker, platform, operator, telemetry, or bridge contract actually owned by the host process.选择由对应 host 进程真正拥有的 scheduler、worker、platform、operator、telemetry 或 bridge 契约。

  3. 03Describe描述

    Declare bundle identity, host API range, components, execution planes, isolation, and permissions in a closed manifest.在闭合 manifest 中声明 bundle 标识、host API 范围、组件、执行面、隔离与权限。

  4. 04Configure配置

    List exact manifest paths; the runtime performs no implicit package or filesystem scan.列出精确 manifest 路径；运行时不会隐式扫描包或文件系统。

  5. 05Admit准入

    Fail closed on schema, API range, duplicate ID, allowlist, permission, or isolation errors before implementation import.在实现 import 前，对 schema、API 范围、重复 ID、allowlist、权限或隔离错误 fail closed。

  6. 06Snapshot快照

    Freeze one deterministic process-local view without resolving domain conflicts generically.冻结确定性的进程本地视图，但不由通用加载器解决领域冲突。

  7. 07Materialize实例化

    Let only the owning domain and execution plane instantiate the component.只允许拥有该领域契约和执行面的代码实例化组件。

  8. 08Verify & roll back验证与回退

    Prove equivalent behavior and failure handling before recommending the typed path; retain a tested legacy rollback.推荐类型化路径前验证等价行为与故障处理，并保留经过测试的 legacy 回退。

BUNDLE ≠ ROLE

Delivery stays separate交付与角色分离

A bundle may contain multiple components. It does not turn a KV system, platform profile, or control plane into one generic plugin.一个 bundle 可以包含多个组件，但不会把 KV 系统、平台 profile 或 control plane 变成一种万能插件。

EXPLICIT DISCOVERY

No ambient scan不做环境扫描

VLLM_EXTENSION_MANIFESTS names exact files. Installed distributions, directories, and networks are not searched implicitly.VLLM_EXTENSION_MANIFESTS 指定精确文件；不会隐式搜索已安装分发、目录或网络。

FAIL CLOSED

Reject before import在 import 前拒绝

Unknown fields, contracts, permissions, isolation, duplicate identities, and incompatible API ranges stop startup.未知字段、契约、权限、隔离、重复标识和不兼容 API 范围都会阻止启动。

PROCESS OWNERSHIP

Materialize by domain按领域实例化

Scheduler and worker connectors remain separate components. The generic loader never chooses provider precedence or invokes hot-path callbacks.scheduler 与 worker connector 保持为独立组件；通用加载器不选择 provider 优先级，也不调用热路径 callback。

PERMISSIONS

Declaration is not a sandbox声明不等于沙箱

Non-empty permissions are denied by default. Trusted in-process code still has host authority; unsupported isolation cannot be claimed.非空权限默认拒绝；可信进程内代码仍拥有 host 权限，不能宣称未实现的隔离能力。

COMPATIBILITY

Behavior, not import success兼容是行为而非 import 成功

Manifest admission proves only static compatibility. A component graduates after domain behavior, failure, shutdown, and rollback tests pass.manifest 准入只证明静态兼容；组件必须通过领域行为、故障、关闭和回退测试后才能毕业。

One materializer does not prove ecosystem compatibility一个 materializer 不代表生态兼容已经完成

Bundle v1 validates and snapshots descriptors before implementation imports. The first experimental materializer supports one exclusive scheduler victim-selector provider; zero typed providers still use the legacy entry point, while ambiguity and typed import or protocol failures fail closed. The KV domain validates exact scheduler, worker, and API-plane telemetry components, explicit ordered composition, and declared HMA, piecewise, and cache-layout capabilities without importing implementations. Typed single and ordered_multi selections now materialize through KVConnectorFactory: configuration checks import nothing, each process imports only its selected roles, declaration mismatches fail closed, and ordered child configuration plus telemetry are keyed by logical connector ID instead of class name. Conflicting ordered layouts fail before import. KVTransferConfig keeps typed and legacy paths mutually exclusive, and the legacy MultiConnector path forwards recovery lifecycle signals across its children. BidKV remains on the compatibility path until its scheduler-policy equivalence and rollback gates pass. The typed KV paths remain experimental until real Mooncake, LMCache, PegaFlow, and LMCache-Ascend equivalence and rollback gates pass. Other domain materializers remain pending.Bundle v1 会在实现 import 前校验并冻结 descriptor。首个实验性 materializer 支持一个独占的 scheduler victim-selector provider：没有 typed provider 时仍走 legacy entry point；多 provider 歧义、typed import 或协议校验失败则 fail closed。KV 领域会在不 import 实现的前提下校验精确的 scheduler、worker 与 API-plane telemetry 组件、显式有序组合，以及声明的 HMA、piecewise 与 cache-layout 能力。typed single 与 ordered_multi 现已通过 KVConnectorFactory 实例化：配置检查不 import 实现，各进程只导入自己的角色，声明不一致则 fail closed，有序子配置与遥测统一按逻辑 connector ID 而非类名关联；layout 冲突仍会在 import 前失败。KVTransferConfig 保证 typed 与 legacy 路径互斥，legacy MultiConnector 路径继续向子 connector 转发生命周期信号。BidKV 在 scheduler-policy 等价与回退门槛通过前仍使用兼容路径；typed KV 路径在 Mooncake、LMCache、PegaFlow 与 LMCache-Ascend 的真实等价和回退门槛通过前仍为实验性，其他领域 materializer 尚未实现。
