Why vLLM-HUST为什么选择 vLLM-HUST

Replaceable policy, state, execution, and hardware paths—with evidence attached.策略、状态、执行与硬件路径可替换，并为结果附上证据。

The technical edge is the combination: programmable scheduling and KV policy surfaces; graph-aware decoding, MoE, and precision paths; explicit Ascend and Metal capability negotiation; narrow control-plane actions; and matched results with exact provenance and rollback. Available code, published work, and open designs remain separate evidence levels.技术亮点来自完整组合：调度与 KV 策略可编程，解码、MoE 与精度路径感知计算图，Ascend 与 Metal 能力显式协商，上层控制动作保持窄接口，并以 matched 结果、精确版本和回退闭合证据链。已有代码、发表成果和开放设计始终分层展示。

vLLM-HUST Plugin StandardvLLM-HUST 插件标准

One lifecycle contract for every plugin.所有插件遵循同一套生命周期规范。

STANDARD 1.0Process-scoped · entry-point based进程级 · 基于 entry point

A conforming plugin can be packaged, discovered, explicitly enabled, verified, stopped, disabled, and removed without editing the vLLM-HUST source tree. The same contract applies on every node and in every worker process.合规插件无需修改 vLLM-HUST 源码，即可完成打包、发现、显式启用、验证、停止、停用和卸载；同一合同适用于每个节点和每个 worker 进程。

  1. 01Create创建

    Isolate code, configuration, tests, and ownership in one package.在独立包中隔离代码、配置、测试和责任边界。

  2. 02Register注册

    Declare one stable Python entry point in the narrowest supported group.在最窄的受支持分组中声明一个稳定的 Python entry point。

  3. 03Package打包

    Build a versioned wheel with compatibility and configuration metadata.构建带兼容性与配置元数据的版本化 wheel。

  4. 04Install安装

    Install into the exact Python environment used by every server process.安装到所有服务进程实际使用的同一 Python 环境。

  5. 05Enable启用

    Select plugins with an explicit VLLM_PLUGINS allowlist.通过显式 VLLM_PLUGINS allowlist 选择插件。

  6. 06Start & verify启动与验证

    Confirm discovery, registration logs, readiness, and one functional request.确认发现、注册日志、服务就绪和至少一个功能请求。

  7. 07Stop & disable停止与停用

    Gracefully stop the server, change the allowlist, then restart.优雅停止服务，调整 allowlist，再重新启动。

  8. 08Remove卸载

    Uninstall only after all consuming processes have exited; verify the entry point is gone.所有使用进程退出后再卸载，并确认 entry point 已消失。

ENTRY POINT

Choose the correct group选择正确的入口分组

vllm.general_plugins for general runtime registration; vllm.platform_plugins only for hardware platforms; vllm.io_processor_plugins for IO processors; vllm.stat_logger_plugins for stat loggers.

PROCESS MODEL

Registration is re-entrant注册逻辑必须可重入

vLLM may load a plugin in API, engine-core, and worker processes. Repeated registration must not duplicate patches, threads, files, or global state.vLLM 可能在 API、engine core 和 worker 进程中加载插件；重复注册不得重复 patch、线程、文件或全局状态。

CONFIGURATION

Namespaced and explicit命名隔离且显式配置

Use plugin-prefixed variables, documented defaults, validation, and safe fallback. Do not embed machine paths, ports, device IDs, credentials, or model locations.使用插件前缀变量、明确默认值、校验与安全回退；不得嵌入机器路径、端口、设备 ID、凭据或模型位置。

COMPATIBILITY

Declare the tested runtime声明已验证运行时

Publish the distribution version, entry-point identity, supported vLLM range, tested vLLM-HUST commit, platform requirements, and incompatible combinations.公布发行版本、入口标识、支持的 vLLM 范围、已验证的 vLLM-HUST commit、平台要求与不兼容组合。

OBSERVABILITY

Make activation visible让启用状态可观测

Emit one registration record with plugin ID and version. Expose readiness or counters without secrets; startup failure must be visible and actionable.输出包含插件 ID 与版本的注册记录；就绪状态和计数器不得泄露秘密，启动失败必须清晰可定位。

SHUTDOWN

Own every resource完整管理自身资源

The plugin owns cleanup for its threads, sockets, files, shared memory, and device resources. Shutdown must be bounded and leave the baseline restartable.插件负责清理自身线程、socket、文件、共享内存和设备资源；关闭过程必须有界，并保证基线可重新启动。

03 / OPERATELifecycle commands生命周期命令
# Deployment inputs
export BUILD_PYTHON=/path/to/build/python
export RUNTIME_PYTHON=/path/to/serving/python
export PLUGIN_WHEEL=/path/to/plugin.whl
export PLUGIN_ID=your-plugin-id
export PLUGIN_DISTRIBUTION=your-distribution-name
export MODEL=your-model
export PORT=your-port

# Build and install into the serving environment
"${BUILD_PYTHON}" -m build
"${RUNTIME_PYTHON}" -m pip install "${PLUGIN_WHEEL}"

# Enable and start
VLLM_PLUGINS="${PLUGIN_ID}" vllm serve "${MODEL}" --port "${PORT}"

# Readiness
curl --fail --silent "http://127.0.0.1:${PORT}/v1/models"

# Stop a directly owned process gracefully
kill -TERM "${SERVER_PID}"
wait "${SERVER_PID}"

# Disable all plugins on the next start
VLLM_PLUGINS="" vllm serve "${MODEL}" --port "${PORT}"

# Remove only after the server has stopped
"${RUNTIME_PYTHON}" -m pip uninstall "${PLUGIN_DISTRIBUTION}"
No hot-unload contract不承诺热卸载

Plugins are process-scoped and may modify multiple vLLM processes. Stop the owning service gracefully before disabling or uninstalling. If VLLM_PLUGINS is unset, vLLM loads every discovered plugin; use an explicit allowlist in production, or an empty string to load none.插件属于进程级能力，可能修改多个 vLLM 进程。停用或卸载前必须优雅停止所属服务。若未设置 VLLM_PLUGINS，vLLM 会加载所有已发现插件；生产环境应使用显式 allowlist，设置为空字符串表示不加载任何插件。

Release checklist发布检查表

What “vLLM-HUST conforming” means什么是“符合 vLLM-HUST 插件标准”

  • Wheel installs without editing the engine tree.无需修改引擎源码即可安装 wheel。
  • Entry point is discoverable and registration passes a double-call test.entry point 可发现，注册函数通过连续调用两次测试。
  • Explicit enabled and disabled startup paths both pass readiness.显式启用与停用两种启动路径均通过就绪检查。
  • Configuration, compatibility, logs, health, shutdown, and rollback are documented.配置、兼容性、日志、健康检查、关闭与回退均有文档。
  • Graceful shutdown releases plugin-owned resources and permits a clean baseline restart.优雅关闭释放插件资源，并可干净重启基线。
  • Smoke results validate lifecycle only; performance claims require a matched benchmark.smoke 结果只验证生命周期；性能结论必须来自 matched benchmark。
